## 実装チェックリスト

### 共通の仕組み

- [x] フォルダを選んでプレビューが表示されるまで待つヘルパー
- [x] iframe 内の要素は必ず `page.frameLocator(...)` で取得する
- [x] テストごとに IndexedDB と Service Worker が前のテストの影響を受けないようにする（新しいコンテキストを使う）

### 必須シナリオ（testing.md）

- [x] **クリック → ツリー選択**: iframe 内の要素をクリックすると、レイヤーツリーの該当ノード（`data-testid="layer-node-<id>"`）が選択状態（`aria-selected="true"`）になる
- [x] **CSS 編集の反映**: エディタで CSS を編集すると、iframe 内の要素の計算済みスタイル（例: `color`）が変わる
- [x] **JS 編集後も HTML/CSS の編集が残る**: HTML と CSS を編集 → JS を編集して確定（iframe が作り直される）→ HTML と CSS の編集が iframe に残っている
- [x] **再読み込みで編集とコメントが残る**: 編集とコメントを追加 → `page.reload()` → 編集が iframe とエディタに、コメントが一覧に残っている
- [x] **Service Worker 初回登録時の表示**: Service Worker が未登録の新しいコンテキストで最初にフォルダを選んだときも、プレビューが正しく表示される（CSS と画像が読み込まれている）

## メモ

### 実行方法

- `pnpm exec playwright test`（`playwright.config.ts` が `vite --port 5173 --strictPort` を起動。`reuseExistingServer` なので、別の worktree の dev server が 5173 を使っていると、そちらを試験してしまう。この worktree のサーバーを使うこと）
- 結果: 9 件（smoke 1 + review 8）すべて成功。`--repeat-each=3` で 27 件すべて成功。tsc / eslint / prettier --check / vitest（676 件）も成功

### 構成（`e2e/`）

- `helpers/fakePicker.ts`: `installFakePicker(page, fixture)`。Node 側で `tests/fixtures/<名前>/` を読み（テキストは文字列、バイナリは base64）、`addInitScript` でページ内に `kind` / `name` / `values()` / `getFile()`（`File`）を持つ偽ハンドルを組み立てて `window.showDirectoryPicker` を差し替える。書き込み系（`createWritable` / `removeEntry` / `getFileHandle` / `getDirectoryHandle`）は呼ばれたら `window.__writeCalls` に記録して例外を投げる。`window.__pickerCalls` は呼び出し回数。`readPickerRecord(page)` で読む。`readFixtureText` は期待値（編集前のソース）の組み立て用
- `helpers/app.ts`: `previewFrame`（`frameLocator('[data-testid="preview-frame"] iframe')`）、`openApp` / `pickFolderAndWaitPreview`、`openFile`（タブか `open-file-select` で開く）、`replaceEditorText`（`.cm-content` をクリック → 全選択 → `insertText`。自動閉じ括弧の影響を避けるため `type` ではなく `insertText`）、`readEditorText`、`waitSaved`、`titleColor`
- `review.spec.ts`: 必須 5 + 追加 3 シナリオ。テストごとに新しいコンテキスト（Playwright の既定）なので IndexedDB と Service Worker は毎回まっさら。固定待ち時間は使っていない

### 網羅したこと

- クリック → ツリー選択（`aria-selected`）、CSS 編集 → 計算済み色、HTML+CSS 編集 → JS 編集して「適用」→ 作り直し後も HTML/CSS の編集が残る（JS が付けた属性で作り直しを確認）、`save-status` が保存済みを待って `reload()` → ピッカー未使用で編集・コメントが復元、初回の SW 登録で CSS と画像（HTML 相対・CSS 相対の背景）が読み込まれる
- 追加: js-slider の生成ドットで `generated-notice` とコメント入力の無効化、broken-html の表示・ツリー・クリック選択（暗黙の tbody 配下の th を含む）、読み込みで書き込み系 API が呼ばれない

### 注意・発見

- 再読み込み後は何も選択されておらず、`h1` などの深い要素の行は折りたたまれた枝の中にあって描画されない（`layer-node-*` が存在しない）。コメントの目印（`data-commented`）はコメントを一覧で選んで枝が開いてから確認している。不具合ではなく仕様
- アプリの不具合でテストを止められたものはなし（`test.fixme` なし、`src/` は未変更）
- 軽微（シナリオには影響なし）: dev server のコンソールに React の警告が出る。`FileTabs.tsx` のスタイルで、ショートハンド（`borderBottom` / `font`）と個別プロパティ（`borderBottomColor` / `fontWeight`）を混ぜている（再描画時に「Removing a style property during rerender」）。05 のチケット側で直すとよい
- 08 のメモにあった「`dist` で共有チャンクを SW が素通りさせるか」は、dev server でのみ検証。`pnpm preview` での E2E は未実施
