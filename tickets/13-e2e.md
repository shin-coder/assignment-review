# 13: E2E テスト

- Wave: 3
- 依存: 12（レビュー承認済みであること）
- 担当ディレクトリ: `e2e/`
- 変更禁止の領域: `tests/fixtures/`（期待値の基準なので書き換えない）、`src/`（不具合を見つけたら該当チケットのメモ欄に書き、そのチケットで直す）

## 目的

`.claude/rules/testing.md` で必須とされている E2E シナリオを Playwright（Chromium のみ）で実装する。

## 関連する設計ルール

- E2Eテスト: Playwright。Chromium のみで実行する
- iframe 内の要素は `frameLocator` で取得する
- テスト用サンプルサイトは期待値の基準なので、テストを通すために書き換えない

## 実装チェックリスト

### 共通の仕組み

- [ ] `showDirectoryPicker` を `page.addInitScript()` で差し替え、`tests/fixtures/<名前>/` の内容から作った偽のディレクトリハンドルを返すヘルパー（`e2e/helpers/`）。ファイル内容は Node 側で読み、`base64` などで渡す
- [ ] フォルダを選んでプレビューが表示されるまで待つヘルパー
- [ ] iframe 内の要素は必ず `page.frameLocator(...)` で取得する
- [ ] テストごとに IndexedDB と Service Worker が前のテストの影響を受けないようにする（新しいコンテキストを使う）

### 必須シナリオ（testing.md）

- [ ] **クリック → ツリー選択**: iframe 内の要素をクリックすると、レイヤーツリーの該当ノード（`data-testid="layer-node-<id>"`）が選択状態（`aria-selected="true"`）になる
- [ ] **CSS 編集の反映**: エディタで CSS を編集すると、iframe 内の要素の計算済みスタイル（例: `color`）が変わる
- [ ] **JS 編集後も HTML/CSS の編集が残る**: HTML と CSS を編集 → JS を編集して確定（iframe が作り直される）→ HTML と CSS の編集が iframe に残っている
- [ ] **再読み込みで編集とコメントが残る**: 編集とコメントを追加 → `page.reload()` → 編集が iframe とエディタに、コメントが一覧に残っている
- [ ] **Service Worker 初回登録時の表示**: Service Worker が未登録の新しいコンテキストで最初にフォルダを選んだときも、プレビューが正しく表示される（CSS と画像が読み込まれている）

### 追加シナリオ

- [ ] `js-slider` で JS が生成した要素をクリックすると、対象外の案内が表示され、コメントを付けられない
- [ ] `broken-html` でもプレビュー・ツリー・クリック選択が動く
- [ ] 読み込んだフォルダに書き込みが行われない（偽ハンドルの書き込み系メソッドが呼ばれていない）

## テストチェックリスト

- [ ] すべてのシナリオが 3 回続けて実行しても安定して通る（`--repeat-each=3`）
- [ ] `tests/fixtures/` を変更していない
- [ ] 固定の待ち時間（`waitForTimeout`）を使っていない
