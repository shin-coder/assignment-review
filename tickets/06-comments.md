# 06: コメントの紐付け

- Wave: 1
- 依存: 00
- 担当ディレクトリ: `src/comments/`
- 変更禁止の領域: `src/shared/`, `package.json`, ルートの設定ファイル, 他層のディレクトリ

## 目的

コメントを DOM ノードではなくソース上の位置（ファイルパス＋位置情報）に紐付け、ソースが編集されても正しい箇所を指し続けるようにする。

## 関連する設計ルール

- コメントは DOM ノードではなく、ソース上の位置（ファイルパス＋位置情報）に紐付けて保存する
- JS が後から生成した要素はソース上に対応する位置がないため、編集・コメントの保存対象外として扱う
- 中核ロジック（コメントの紐付け）には必ず Vitest の単体テストを書く

## 実装チェックリスト

- [ ] `createComment(info: ElementInfo | null, body)`: 要素の位置から `ReviewComment` を作る。`info` が `null`（JS 生成要素など、ソース位置がない）の場合は作らずに理由を返す
- [ ] `shiftLocation(location, change: TextChange)`: 編集による位置のずれを計算する
  - [ ] 変更がコメント範囲より後ろ → そのまま
  - [ ] 変更がコメント範囲より前 → 差分だけずらす
  - [ ] 変更がコメント範囲の内側 → 範囲を伸縮する
  - [ ] 変更がコメント範囲を完全に含む（要素が消えた） → 失効（`orphaned`）
  - [ ] 範囲の一部と重なる場合のルールを決めて実装する
  - [ ] 別ファイルの変更は影響しない
- [ ] `applyChangesToComments(comments, changes)`: 複数のコメントに複数の変更を順に適用する
- [ ] `resolveCommentElement(comment, map: ElementSourceMap)`: コメント位置に対応する現在の要素 ID を返す（レイヤーツリーやプレビューで強調表示するため）。見つからなければ `null`

## テストチェックリスト

- [ ] `shiftLocation` の各ケース（前・後ろ・内側・完全に含む・一部重なる・別ファイル）
- [ ] 同じ位置への挿入（コメント範囲の開始位置ちょうど／終了位置ちょうど）の扱い
- [ ] 複数の変更を順に適用した結果が、まとめて適用した結果と一致する
- [ ] ソース位置がない要素ではコメントが作られない
- [ ] 要素を編集した後も `resolveCommentElement` が同じ要素を返す（04 の解析結果相当のデータを手で作ってテストする）
- [ ] 要素を削除すると `orphaned` になり、`resolveCommentElement` が `null` を返す
