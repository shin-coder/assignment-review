# 03: ソース管理層と IndexedDB 保存

- Wave: 1
- 依存: 00
- 担当ディレクトリ: `src/store/`
- 変更禁止の領域: `src/shared/`, `package.json`, ルートの設定ファイル, 他層のディレクトリ

## 目的

元のソース・編集後のソース・コメントを 1 つのプロジェクトとして保持し、IndexedDB に保存・復元する。ブラウザを再読み込みしても、フォルダを選び直さずに作業を再開できるようにする。

## 関連する設計ルール

- ソース管理層: 元のソース・編集後のソース・コメントを保持し、IndexedDB に保存する
- 編集やコメントは一時的に見せるためのもので、生徒に渡すファイルは作らない
- 中核ロジック（保存と復元）には必ず Vitest の単体テストを書く

## 実装チェックリスト

### ソース管理（メモリ上）

- [ ] `SourceStore` クラス（または同等の関数群）を作る
  - [ ] `getOriginal(path)` / `getEdited(path)`（未編集なら元のソースを返す）
  - [ ] `setEdited(path, text)` / `resetFile(path)` / `resetAll()`
  - [ ] `isEdited(path)` / `editedPaths()`
  - [ ] 変更を購読できる `subscribe(listener)`（React 側で再描画に使う）
- [ ] 元のソースは読み込み後に変更できないようにする（`setEdited` で元を書き換えない）
- [ ] コメントの追加・更新・削除・一覧（紐付けの計算は 06 の担当。ここでは保持だけ）

### IndexedDB 保存

- [ ] `src/shared` の `ProjectRepository` を `idb` で実装する（`IndexedDbProjectRepository`）
  - [ ] DB 名・バージョン・オブジェクトストアを定数で定義し、`upgrade` でスキーマを作る
  - [ ] `ArrayBuffer`（画像）も保存・復元できる
  - [ ] `Map` は保存できる形（配列など）に変換し、復元時に戻す
- [ ] 編集・コメントの変更時に自動保存する（短時間の連続変更はまとめる。デバウンス時間は定数）
- [ ] 最後に開いていたプロジェクト ID を保存し、起動時に復元できる `loadLatest()`
- [ ] 保存失敗（容量超過など）を呼び出し側に伝える

## テストチェックリスト

- [ ] `fake-indexeddb` を使い、保存 → 新しいリポジトリインスタンスで読み込み → 内容が一致する（テキスト・バイナリ・編集後ソース・コメント）
- [ ] 未編集ファイルは `getEdited` が元のソースを返す
- [ ] `resetFile` / `resetAll` で元に戻る
- [ ] 元のソースが編集で変わらない
- [ ] 自動保存のデバウンス（偽タイマーで、連続変更が 1 回の保存になる）
- [ ] `loadLatest()` が最後のプロジェクトを返す／何もなければ `null`
- [ ] `remove()` 後は `load()` が `null`
